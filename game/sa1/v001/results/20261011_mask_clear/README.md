# 占有マスクによる消去の細分化

各raw面の旧占有マスクを保存して、占有していたタイルだけを消す四方式を実測した。元の最小・最大範囲より消去バイト数は減るが、区間走査と消去の設定が増えて遅くなった。公開ROMは変更していない。60fps達成の証拠には使わない。

|方式|800fieldのlogic/表示|2field間隔|画素一致|
|---|---:|---:|---:|
|公開固定map版（既存比較）|654/647|4|168|
|専用BW配置表（既存比較）|656/645|4|168|
|占有ビット走査＋stack消去|648/637|11|168|
|占有ビット走査＋DMA優先|648/637|11|168|
|8bit表引き＋DMA優先|651/640|8|168|
|表引き＋2タイル以下の隙間を統合|651/640|8|168|

四方式とも実PPUの参照位置から168画面を照合し、同じ入力列のsprite packetも共通世代まで一致した。`comparison.json` にROM SHA、最大描画時間、間隔の実測値を保存。`commands.json` が再現用ビルドコマンドで、`evidence.zip` に各計測のmetadata、trace、VRAM、raw、画像などを保存した。

新しい履歴は43:2300..259F、旧マスクの作業域は43:2600..265Fを使う。待機中の先行消去が完了した帯は、この履歴も空へ変更する。DMAの零源は03:F000..F3FF。8行の各区間にわたって進むDMAのsourceが1KiBを越えない構成で、DMAエンジンが使用中なら既存stack消去へ戻す。
