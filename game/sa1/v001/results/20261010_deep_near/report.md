# 7枚保持と近景OBJの検証（作業継続中）

60fpsはまだ全条件では達成していない。公開ROMは変更していない。

BW-RAM内の7枠を0400/8400からの24KiB画像として使い、先頭1KiBをクリップ保護にした。左端にかかる画像のindexedアクセスが隣bankへ届いて先頭行を壊す問題は、この余白を入れた試験で解消した。metadataはWRAM A000以降へ移し、8枠へ拡張。7枚を描き溜めて開始するため、入力から表示までの遅延が増える。

初期7枚版のSHA `865af048...` は、include末尾のsegment復帰漏れでINIDISP用HDMA表の参照先が誤っていた。`movestress_deep7`、`bossdeep7`、`bossmovestress_deep7` の結果は**ハードウェア設定不正のため性能根拠から除外**する。JSON内の旧goal判定がtrueでも成功ではない。配置を修正し、実際のforced blank状態とHDMAによる不正なunblankも検査へ加えた。

近景は元画像の62種類の8x8タイルを反転共有してOBJへ移し、遠景はBG2へ分担する。前景二面の表示されない先頭タイル行へ遠景の64タイルを置き、空いたVRAMへ近景を保持する。近景33列のうち6列（48px）は同じ画像をSA-1で描き、残る27列をOBJへ置く。自機を含めて走査線あたり最大29 OBJ・31タイルで、SNESの上限内。自機の16x16はOBSELのlarge側へ移し、絵は維持する。合成結果を独立参照と照合する。

segment修正済みSHA `c2d08109...` は移動450field/358枚・123画面一致で毎field表示。しかしボス移動1800fieldでは1317枚・139画面一致、2field間隔289回などが残った。CPU側の近景OAM作成と転送量の大きい画像が問題。速度の根拠と画像一致の根拠を区別する。

現在は512水平位置の近景OAM記述子を128KiBのROM表にし、DMAでコピーしてYだけ合わせる試作を検証中。ROM表はC0の重複boot領域とDEの未使用になった背景展開表へ置く。DA..DDの地面paletteとDFの自機画像は保持する。初期案のDC/DD上書きは地面色を壊し、追加したCGRAM照合で検出したため不採用。

`measurements.zip` は途中の計測・画素証拠、`index.json` は実測の一覧。hardwareValid=falseの行は失敗例。最終成果ではない。
