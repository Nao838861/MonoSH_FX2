# 逆順native行と左右クリップの比較

60fps維持は未達。独立したSA-1分岐で、素材・全1,492寸法・物量・通常クロックを保持して比較した。配布ROMは更新していない。

|道中800フィールド|論理世代|表示枚数|実PPUを含む画素一致|1フィールド間隔|2フィールド間隔|最大SA-1時間|
|---|---:|---:|---:|---:|---:|---:|
|v1: 逆順native行＋右端の別表|655|644|168|636|5|22.357495ms|
|v2: 右端ポインタを行headerへ配置|654|643|168|634|6|23.362185ms|
|v3: 左端の爆発39にもhash検索を追加|654|643|168|634|6|23.362185ms|
|v4: 左端も行headerから直接参照|656|645|168|638|4|22.783620ms|
|v5: 右端は別表、左端はheader直接参照|656|645|168|638|4|22.778591ms|

表示間隔は初期2枚を除外。起動準備を含む表示枚数を800で割ってfpsとはしない。既存のBW map方式も645枚・2フィールド間隔4回なので、v4/v5は今回の試作内では改善したが従来最良の道中表示を越えていない。全試作で元のゲームと共通する世代のpacketを照合した。

右端からはみ出した大きな爆発だけ、行を右から左へ生成し、見えないwordの命令を飛ばす。通常の65816 stackを維持してIRQへ戻れる。対象は素材40/41の幅91以上で、実際には91/94/97/100/128を保持する。幅91・中心255の同じ爆発は、従来約5.462msからv1約2.784msへ短縮した。ただし全画面に収まる場合にも逆順kernelを使用するため、全体が同じ比率で速くなるわけではない。

左端は草・木0/2/3/5の幅64以上と爆発39の幅79以上を対象とした。hash検索を各行に追加したv3は速度を悪化させる場合がある。v4/v5は圧縮hintへの24bitポインタを行headerへ配置し、検索を除去する。同じ幅79・中心25の爆発はv3の6.519264msからv4の4.515378msへ短縮した。全体では完成画像の待ち行列が空になる区間が残り、その間はSA-1がまだ描画している。単なる切替設定の問題として扱わない。

静的検証では元ROMに対して全1,492寸法、native行90,854回、弾の圧縮行158,688回を照合した。逆順の1,557kernel・右端59,519境界、左端6,326kernel・190,929ケースも全結果一致。左端hintは全104,953境界を保持し、75,687bytesから37,761bytesへ圧縮する。v4/v5では49,152bytesのhash表を廃止する。検証ツールは実ROMの全対象寸法からheaderをたどり、補助JSONの列挙だけに依存しない。

Mesenの実PPU状態と表示VRAMを含む境界テストは、v1右端548画面、v3左端500画面、v4左端500画面・右端548画面、v5右端548画面で全画素一致し、末尾停止はない。短い境界fixtureの合格はゲーム全体60fpsの根拠にはしない。

v5の最初のホスト実行はPythonのFraction演算中の例外で、次の実行はMesenプロセス終了で完走していない。どちらも性能・正しさの根拠から除外し、ログだけを別枠で保存した。同じROMの再実行が800フィールド・168画面一致まで完走した。ROM不具合かホスト側かの原因は、この記録だけでは確定しない。

再現コマンドはcommands.json。各build直後に該当scenarioをtest_sa1_game.pyで実行し、Pythonによる画素照合終了までROM/LBLを変更しない。verify_sa1_reverse_explosions.py、verify_sa1_left_hints.py、analyze_sa1_hint_compression.pyで静的確認を行う。report_sa1_reverse_game.pyがROM・labels・manifest・packet・実PPU状態・全画素照合用データをevidence.zipへ収め、comparison.jsonへSHAを記録する。

次は負荷集中時の描画と消去の総量を減らす必要がある。右端の単体高速化やhint容量削減だけで60fps達成とはしない。
