# 炎3位相の左端描画とボス戦の長時間比較

60fps維持は未達。配布ROMは更新しない。逆順native版の左右clip改善をボス戦へ延長すると、従来の配布固定map版より遅かった。そこで左端の炎31も行headerのhintポインタから描く比較と、投影表をWRAMへ戻す比較を追加したが、全体改善にはつながらなかった。

|ボス戦1,900フィールド|logic/表示|画素一致|表示間隔フィールド数:回数|最大SA-1時間|
|---|---:|---:|---|---:|
|配布固定map版（既存比較）|1748/1742|147|1:1731、2:8|21.865999ms|
|逆順native v5、炎は既存描画|1705/1702|146|1:1654、2:45|19.229351ms|
|炎64/66もheaderから描く|1701/1698|146|1:1647、2:47、3:1|22.773749ms|
|上記＋投影表をWRAMへ配置|1701/1698|146|1:1647、2:47、3:1|22.773749ms|

全試作で実PPUの参照先・表示VRAM・paletteを含めて画素一致、末尾停止なし。同じ入力の共通logic世代のpacketも配布版と一致する。起動準備・先行保持枚数が違うため、表示枚数だけのfps換算はしない。最大SA-1時間が小さい逆順v5も表示落ちは増えており、最大値の比較だけで採用を判断できない。本体CPUの通常処理と転送を含む継続的な供給が必要になる。

炎31には3色位相があるため、全対象寸法の各phase×横2位相を列挙する。左端hintの対象は従来6,326kernelから6,546kernelへ増え、実ROMから得た196,569の左端ケース、108,103のhint境界を照合した。元の全1,492寸法・native行・弾データは保持する。

専用fixtureでは幅64/高さ63と幅66/高さ65、色位相0/1/2、横中心7位置、bottom3位置の全126組み合わせを表示側のmetaから確認した。300画面が実PPUを含めて一致した。geometryとphaseを同じ周期にすると組み合わせの抜けが起こるため、専用fixtureではphaseとbottomを独立に進める。最初の汎用fixture500画面はこの全組み合わせの証拠には使用していない。

`--left-flame-hints`は`--left-inline-hints`の比較用オプションであり、既定ではない。投影表をWRAMへ置く時も逆順行の実行部にROM投影表への依存はなく、既存のCPU CODE配置検査とROM領域非重複検査を通す。今回のWRAM化で表示間隔は変わらなかった。

コマンドはcommands.json、集計・SHAはcomparison.json。evidence.zipに各試作ROM・labels・manifest・静的検証結果と新しい全照合用データを収録する。配布版は既存検証のsummaryを参照比較として収録した。

次の道中の候補は右端爆発の対象寸法拡張。現在は幅91以上だが、残る待ち区間では幅76/79/82/85/88も重い。幅88・中心234の爆発41は約4.864ms。元のkernelを置き換える方式なので追加コード全体を単純に二重保持する必要はないが、native ROMの残量と別表selectorの件数上限を確認してから拡張する。WRAM投影版のDF0000..6FDEには非zeroデータが8,130B残るため、空き領域として無条件に使わない。
