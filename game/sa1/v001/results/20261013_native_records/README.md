# native行の再利用による右端別表3byte化

60fps維持は未達。全素材・全1,492寸法・通常クロックを維持する独立SA-1分岐の比較。公開ROMは更新しない。

右端用の各行recordをhint pointerの3byteだけにし、code pointer・描画位置・extentは既存のnative行とkernel headerから読む。6byte方式で不足した幅79を、hint非圧縮で収められた。ただし追加読出しや右向きkernelの命令数も含めて全体を測ると、表示速度は改善しなかった。

|道中800フィールド|logic/表示|実PPUを含む画素一致|表示間隔フィールド数:回数|最大SA-1時間|
|---|---:|---:|---|---:|
|従来の逆順幅91・v5（既存比較）|656/645|168|1:638、2:4|22.778591ms|
|幅79・3byte行情報・hint非圧縮|655/644|168|1:636、2:5|23.144466ms|
|幅76・3byte行情報・hint圧縮|654/643|168|1:634、2:6|24.105575ms|
|従来v5＋左端の定数探索をbyteで実行|655/644|168|1:636、2:5|25.606418ms|

共通logic世代のpacketは配布固定map版と一致し、全6試験で末尾停止はない。初期2枚を除いて表示間隔を数え、表示数を起動準備込みの800で割ってfpsとはしない。最大SA-1時間や短いfixture単独では採用を決めない。

幅79の別表は21,003bytes、hintは9,813bytesで非圧縮。2,726個の逆順kernelを使用し、右端の全97,388境界を元の描画へ照合した。元のnative/弾の行も全て保持する。

幅76の非圧縮版は右端行情報領域不足でビルドを完了しなかった。圧縮すると18,007bytesに収まり、hintは10,219→5,357bytes。3,030kernel・右端106,488境界を検証した。境界数は各snapshotのreverse_explosions_verified.jsonにも保存する。失敗版の性能値はなく、ログを証拠へ別枠で収録した。

幅79/76の専用fixtureは各500フィールド・348画面で実PPU状態、VRAM、paletteを含む全画素一致。表示済みmetaから幅79の高さ61/62、幅76の高さ59/60、素材40/41、横中心13位置、上端7位置の各364組み合わせを確認した。最大時間はそれぞれ8.180275ms、9.264771ms。両者は絵の寸法も違うので、この最大値の差を方式単独の速度比としない。

左端では、途中のSTA命令から再開する際に直前のLDA定数を探す処理を8bit化し、繰り返しのmask演算を省く比較を追加した。別の新flag --left-byte-constant-scanで既定OFF。草木・爆発を含む専用fixture500画面は一致し、最大13.419768msだったが、道中では上記の通り悪化した。命令数が減ったことだけで全体改善を主張しない。

全試作の静的検証は元ROMの全1,492寸法、native行90,854回、弾の行158,688回、左端6,326kernel・190,929ケースを確認する。--reverse-records-nativeはcompact/inline形式と同時使用しない。native行・hint列の最初の表示行と毎行の進め方も実PPU fixtureで検証する。

再現コマンドはcommands.json、集計とSHAはcomparison.json。tools/report_sa1_native_records.pyがROM・labels・manifest・静的証拠・全画素照合用データをevidence.zipへ保存する。

次は描画helperをI-RAMへコピーし直す費用を確認する。現在の左helperは423bytes、逆順helperは幅79非圧縮354bytes・幅76圧縮465bytesで、いずれも0300..04FF内に収まる。弾コードと大きな端の退避領域も同じ場所を使用するため、再利用する場合は上書き箇所を明示的に追跡し、弾・左右端・通常描画を混ぜた画面で照合する。容量削減版を配布版へ昇格させない。
