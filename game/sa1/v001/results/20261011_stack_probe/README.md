# スタック書き込みの速度試験

既存55fixtureでPEAによる2byte書き込みを測り、全件画素一致を確認した。

| 固定fixture | 最大描画時間 | 全面消去込み |
|---|---:|---:|
| 通常のコンパイル描画 | 7.583ms | 12.171ms |
| 位置既知、fixture全体でスタック描画 | 5.546ms | 10.134ms |
| 通常描画、行ごとの呼出し | 7.085ms | 11.673ms |
| 行ごとにBW map・スタック設定と復帰を実行 | 9.233ms | 13.821ms |

位置・寸法の検索、ゲーム処理、PPU転送は含まない。速い二件目はfixture全体で割り込みを止めるため、ゲームへそのまま入れない。最後の方式はSA-1の8KiB BW mirrorの設定とスタックの復帰を行ごとに実行し、通常の行描画より遅くなった。

最初のスタック試作はDB=40の状態で2225へabsolute書き込みを行い、BW mapが切り替わらなかった。bank zeroへのlong書き込みに直し、55fixtureを再実行して一致したものだけを記録した。

再現は `build_sa1_planar_probe.py --packed-stack`、`--packed-native --row-calls`、`--packed-stack --row-calls` と、それぞれ直後の `test_sa1_probe.py`。以後の候補は、8KiB境界を越えない少数行のまとまりでmapとスタックを一度だけ設定する方式。まだ実装・実測しておらず、60fps達成ではない。
