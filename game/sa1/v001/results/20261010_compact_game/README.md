# ゲーム処理を8KB窓へ移す検証

全体60fpsは未達。画像・色・輪郭を変えず、描画用BW-RAMを7面維持したままゲーム更新をSA-1へ移せた。ただし、ゲームを本体CPUで更新する従来の最良構成より速くならなかった。公開ROM・起動用cmdは更新していない。

## 配置

旧 `--sa1-game` のBW40全64KB複製・描画5面に対し、新 `--sa1-game-compact` は次の配置を使う。ゲームコードは既存C1を共有し、別リンク・コード全複製は不要になった。

| 用途 | 配置 |
| --- | --- |
| 不変データ | 02:8000以降のROM、本体WRAMの8000以降と同じ内容・ポインタ値 |
| ゲームのDATA/BSS | 6000..77FF。SA-1は2225=1BによりBW43:6000へ対応 |
| ゲーム固定scratch | BW43:7800..7AFF。workerのIRAMを壊さない |
| worker/gameのDP退避・入力 | BW43:5000、5100、5200 |
| ゲームC stack / hardware stack | 7C00 / 7FFF。境界には独立した検査値を配置 |
| 地面生成コード | C3へ移動 |
| 起動時VRAM画像 | C2後半へ23,433Bの可逆圧縮。展開後は元の65,536Bと一致 |

本体WRAMのBSSを6000、RODATAを8000、COLORBSSを2000へ移した。音声イベントとソート用リストもSA-1から届くBSSへ移した。本体CPUは必要な描画命令・OBJ・地面状態・音声用状態だけを受け取る。ボス爆発の高さ計算は本体乗算器へ触れない同値の計算へ変更した。SA-1ゲームが4202..4206へ書くと試験を停止する。

ゼロ消去元だった02:8000はRODATAに変わるため、消去DMAを03:F000へ移した。初回試験でこれを検出した画素不一致も証拠に残す。専用のゼロ1KBがROM生成後もゼロであることをassertする。

## 実測

起動時展開で開始が約64フィールド遅くなるため、総表示枚数だけを以前の起動時間が短い版と比較してはいけない。

| 構成 | 試験フィールド | 表示枚数 | 最初の表示 | 画素一致 |
| --- | ---: | ---: | ---: | ---: |
| 配置だけ変更、ゲームは本体CPU | 800 | 641 | 154 | 128 |
| SA-1ゲーム、期限4行追加確保 | 800 | 616 | 156 | 128 |
| 上記＋CPU費用表＋dirty-iram | 800 | 608 | 156 | 128 |
| 上記＋本体IRQをWRAM実行 | 800 | 609 | 156 | 128 |
| 上記＋本体のゲーム待機をWAI | 800 | 620 | 156 | 128 |
| ボス・WRAM IRQ、通常待機 | 1800 | 1317 | 157 | 139 |
| ボス・WRAM IRQ、WAI待機 | 1800 | 1406 | 157 | 141 |
| 色・反転・縮小・端のfixture、WAI | 313 | 120 | — | 120 |

WAI版の道中ゲーム処理は平均2.32ms、通常待機のWRAM IRQ版は3.13ms。待機ループによるROMアクセスを減らす効果はあった。しかし、SA-1の描画とゲーム更新が同じ計算資源を使い、全体の60fps維持には届かなかった。ボスWAI版の表示間隔は1フィールド1,172回、2フィールド225回、3フィールド6回。平均値で60fps達成とは扱わない。

同じ論理入力を与え、配置のみ変更した版と各SA-1ゲーム版の描画命令を世代ごとに比較する。初期の2構成は622/614世代で完全一致した。WAIを含む最終比較の世代数と全ROM SHAはcomparison.jsonを正本とする。画素・VRAM・パレット・HDMAの参照比較、表示順、実DMAのゼロ長・非表示期間、両stackの境界・C stackの復帰も検査した。

初期SA-1ゲーム版は表示切り替えが非表示を越えて停止した。期限を4行確保した費用表版もボス戦で26行まで遅れたため、成功試験としては扱わない。その停止までの135画面は別途画素比較を通した。WRAM IRQ＋WAIのボス長区間は転送・切り替え検査も完了している。ROM競合の寄与は推測を含み、全ての遅延の原因を確定したという意味ではない。

## 再現と証拠

共通の描画構成はraw7面・VRAM3面・direct-sparse・prefix-fastrom・連続CHR DMA・左端hint・bullet-words/opacity・idle-clear。`--compact-memory` は配置変更だけ、`--sa1-game-compact` は配置変更とSA-1ゲーム更新を有効にする。後者の追加比較は `--prefix-cpu-table --dirty-iram --game-irq-wram --game-wait-wai`。完全な最終ビルド引数はbuild_command.txtに保存する。

`python tools/report_sa1_compact_game.py` でcomparison.jsonとevidence.zipを作る。zipには失敗ログを含む各試験の画面・VRAM・描画命令・Lua・計測、および最終実験ROM・配置・ラベルを収録する。失敗試験を完走試験へ混ぜない。最終実験ROMは比較用であり、遊ぶための公開ROMを置き換えない。

次は従来の最良構成へ戻り、毎表示1,472Bを使うマップ転送など、実転送量を減らす方法を検討する。元画像・縮小寸法・描画世代・表示領域は維持する。
