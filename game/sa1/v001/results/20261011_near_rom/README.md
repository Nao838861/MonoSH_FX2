# 近景のROM断片直接描画

中央48/52pxの近景を8px断片と末尾4pxの断片で描く `--near-rom` を追加した。元のROM→IRAMコードコピーを省き、全512開始位置・9行の同じ絵を描く。8px側はFE0000から41,952B、4px側はFEC400から13,525B。左端hintの末尾7EC39Fと重ならず、使用前の領域が零であることをビルド時に検査する。

800fieldで655logic/644表示、2fieldの表示待ち5回、168画面が実PPU参照から一致した。同一入力のpacketも共通世代まで一致した。最大SA-1時間22.743112ms。比較元の安全BW配置表版は645表示・4待ちで、改善しないため公開ROMへは採用していない。60fpsは未達。

初回v1では共有07F0のopcodeをJMLに変えたあと戻さず、後続spriteの戻りstackを壊した。毎行終了時JSLへ戻すv2で再測定した。v1は速度・正しい表示の証拠から除外する。

全48/52px窓をそれぞれコード化する方式も容量だけ測ったが165,953Bで元の45KiB領域を越える。各窓を4〜28pxに分けても、そのままでは入らない。今回の方式は周期512px上の全開始位置の断片を共有して収めている。データ生成と容量検査は `tools/sa1_near_patch_rom.py`、実機コードは `near_rom_game.s`。再現コマンド・ROM SHA・間隔は同ディレクトリのJSON、画像とtraceはevidence.zip。
