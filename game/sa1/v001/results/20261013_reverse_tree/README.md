# 木の逆順native描画

60fpsは未達。独立SA-1分岐で全44素材・1492寸法・色・物量・通常クロックを保持して実装・比較した。公開ROM9934d77bは維持し、作業用の既定ROMもa9bcd247へ戻した。新経路は既定OFF。

木4の全76寸法を右wordから描くnative行へ置き換えた。右端では、隠れた部分を飛ばしたROM命令へ直接入り、行コードのコピーと画面外の退避・復元を省く。左端・画面内は従来のchunk経路を使う。共通hintは211種類、各kernelのheaderには1byteの番号を置く。raw hint2356Bとpointer表633BはDF6FE0..DF7B8Cへ配置。圧縮hintより1007B増えるが、実行時の復号を省いた。

元の順方向nativeを二重保持しない。木4の5751 kernel・9336行は元と同じmask/valueになり、全90,588右byte境界で可視suffixも一致する。全素材の90854 native行使用・158688弾行使用、全5992 dirty縦位相表も照合した。他素材と共有していたkernelを残す分を含め、全体のnative codeは3701091→3716029B。dirty表にはbank末尾の読出し用余白も追加した。bank詰め物8876Bを再利用し、左clip表11776BをDF9200..DFBFFFへ置く。最終payloadEndは7ED94Bで8MiB内に収まる。各予約域の上書き検査を通した。

無効比較はROM内のdispatch6Bとchecksum4Bだけを変え、全labels・nativeデータ・helperの配置を揃えた。既存コードの複製側に差分は無く、全差分は10B。無効版は逆順の木を従来chunkで描く。したがって27→24待ちは、ROM配置の変更だけでは説明できない。前段基準との28→24では、そのほかの配置変化も含む。

3版とも基準との共通3826世代のpacket・全framebuffer、3827世代のtile maskと消去端、3826完了更新のゲーム状態が一致した。死亡・地上の死亡状態・復帰・ボス移行も同じlogic番号。新しい木の経路は68物体・4208行を通り、そのうち3376行は隠れたコードを飛ばした。個別の短縮例は68×158の右端の木10.929→4.284ms、64×148で9.140→5.788ms。物体時間はIRQ・共有バスの影響を含み、全場面で同じ短縮率になるとは扱わない。

併用版の境界試験は、全76寸法×左右12位置×上下3位置の2736ケースを1369画面で照合し、全画素一致。最初の1画面は起動時の通常packet。上端・下端・左右の偶奇・画面内・完全に画面外を含む。1366定常区間が毎field更新でも、限定fixtureのため全ゲーム60fpsとは判定しない。

併用版のボス5000fieldは4835表示・1:4817/2:15・最大22.439815ms・198画面一致。前段の草木右端版は4834表示・16待ちで、共通4840世代の全framebufferと4839完了更新のゲーム状態が一致した。HP0、boss state 2/3、stageへ戻り、注入で再びボスに移行するところまで記録。開始条件とstage frameを注入し無敵化しているため、自然なクリア確認とは区別する。このボス試験では木の新helperを通っていないので、1待ちの差を木の高速化効果とは解釈しない。

## 初回の停止と切り分け

初回8f2a3888は境界1369画面が一致したが、通常試験が約380fieldで不完走になった。診断でfield265、master clock94739822、PC E2C7におけるdirty範囲表の読出しを捕捉した。草0・53×29・縦位相1の末尾recordは95FFFDの042701。runを16bit LDAで読むため95FFFFの次の960000まで読み、LoROMの未割当領域へ出ていた。論理的な表内容は変えず、各phase末尾へ1byteの余白を確保し、静的検査も末尾の余分なhigh byteまでbank内であることを確認するよう改めた。

ただし、この読出しだけを停止原因と断定できない。計測callbackも、helperへ入った直後の未初期化作業値を読まないよう変更した。同じ旧ROMへ安全なcallbackだけを適用した600field再生は451表示・125画面一致で完走し、bank外読出しの警告自体は残った。初回停止の原因は一意に確定していない。ROMの余白修正とobserverの修正を分けて記録し、修正版の通常4000field・ボス5000field・境界試験の完走を採用根拠とする。旧ROMの短い完走を旧版の全体合格には戻さない。

初回のLua・ROM・ログ・未完了capture、診断のCPU/DP状態、同じ旧ROMのobserver比較を歴史資料として保存した。診断はreadを捕捉して意図的に停止し、速度評価には使わない。修正版の静的検査と実画面検査を、初回ROMの合格結果へ混ぜない。

## 残る負荷

併用しても通常で23待ちが残る。最大24.084716msのjobはdirty計画3.790239ms・消去3.698701ms・背景0.287094ms・描画16.308682ms。左端の66×152の木には9.606msかかる。右端の短縮だけでは左端の画面外描画と退避・復元は減らない。CPU側もIRQを除いたlogic観測値が最大13.704068msで、SA-1の時間へ足して単純な合計時間にしない。

次の候補は、同じ逆順hintを左端の可視prefixの終端にも使い、行コードだけをIRAMへ保持して再利用する方法。計測で重かった66×152・left=-34について、152行のうち135行がprefix対象。同じcode/clip位置を保持する試算では54回を再利用でき、コピー量は5910→3552Bになる。まだ実装・実速度の証拠ではない。再利用は物体内に限定し、他のhelperがIRAMを上書きした後には使わない。左端のwordが前行へ書く1byteの保護、DMA使用中のfallback、上下端を確認してから比較する。

commands.jsonは現在のビルド・試験コマンド、comparison.jsonは集計と全zipのSHA。caseごとのzipに全世代framebuffer・packet・VRAM・PPU・palette・RGB・Lua・計測を保存。roms_sources_history.zipに4版のROM/labels/map、source・静的結果・旧版切り分け・次案のコピー量probe・既定復元を保存した。PNGはRGBと重複するので除く。既定復元280fieldは138logic/131表示・120画面一致・最大7.241609ms。Mesenの通常クロックでの結果で、実機計測は未実施。
