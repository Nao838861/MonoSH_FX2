# 切替準備・DMA設定・転送予約の比較

60fpsは未達。前回の一本化192版から、画面切替の準備、転送先の事前計算、I/O書込み、展開個数、転送予算を順に変更した。道中の最良結果は従来と同じ3回待ち、ボスは2回待ちで、通常設定・公開ROMへ採用しない。素材、1492縮小パターン、描画順、物量、ゲーム時計は維持した。

## 変更

- `--early-flip-prepare`：recordからWRAMの次画面状態を準備し、実PPU操作の直前で非表示を待つ。実行時にHDMAの表・間接参照先が準備用metadataと重複しないこと、PPU更新が非表示期間内であることを検査する。
- `--prebank-dma`：SA-1の世代0198から交互のVRAMページを決め、記述子の宛先にページを加算済みにする。S-CPUの各転送直前の加算を省く。途中分割した宛先も絶対アドレスのまま進める。最初の対照ROMは費用57を維持したが、現在のsourceでは削減命令に対応して4を割り引く。
- `--dma-short-io`：DMA展開区間だけDBを00にし、WRAMからの読出しをlong、I/O書込みをabsoluteにする。D=4200と16bit STYでのDMA開始は維持し、DB/Dを復元する。費用をさらに2割り引く。組合せ版の記述子費用は51。
- `--dma-unroll-count 16/20`：一回の展開を12記述子から増やし、まとまり間の設定を減らす。20個版のCODEはFFF9 byteで、64KiBの残りは7 byte。無制限に展開できない。
- `--prefix-refresh-sixteenth`：データ費用を`n+n/32+n/128`から、追加`n/16`を含む形へ変更し、途中分割済み量の控除も同じ式にする。試験ではsmall予約1600/player2400を併用した。全量の安全余裕を一律に下げる旧案とは区別するが、表示結果は退行した。
- `--tail-flip-reserve 1400`：自機CHR更新が不要で残量1024byte以下の場合だけsmall予約を1400にする。大口の2200と自機更新時2300は維持する。待ち回数は変わらなかった。
- 既存の`--sparse-merge-gap 32`も現行基準で再比較した。小さな透明区間を一緒に送る方式だが、待ちは減らなかった。

## ボスと分割転送

ボス1900フィールドは、切替準備版・20個展開版・少量予約版の全て1748表示、1フィールド間隔1743回、2フィールド間隔2回。147画面ずつ照合した。最大SA-1時間は順に18.487823、18.607484、18.470223msで、前回の1748表示・2待ちを上回らない。共通世代の全バッファ等も比較する。

元の爆発40/41を94×74で9個描くtransferfixtureを500フィールドずつ実行。追加refresh版は145表示・全145画面、少量予約版は144表示・全144画面が一致した。途中転送からの再開、両方のVRAMページ、元の記述子長と現在の残量からのprefix選択を検査する。fixtureは2～3フィールド間隔で、ゲーム60fpsの達成には数えない。原画の配置以外をホストが描画していない。

実ROMの探索命令59024条件、全量判定58148条件、予算表262144条件を保存した7候補ROMで検証。最終の少量予約版では全1492寸法・native90854行・弾158688行が基準ROMと一致し、dirty5992縦位相表も元画像alphaからの独立計算と一致した。新しい費用式のROMでは、SA-1が作った累積byte数と費用を実行時に別の式で再計算して照合した。

短いI/O版の最初のharnessは、Mesen stateのDBを`cpu.db`という誤ったキーで読んで停止した。実際は`cpu.dbr=126`、D=0で復元されていた。キーを修正し、同一ROMを800フィールド最初から再実行したv2だけを性能比較に使う。初回のLua・failure・stateは証拠内へ分離保存した。

## 次の候補を実データで確認

tools/probe_sa1_fixed_front_mask.pyは、現在の占有maskと一世代前／二世代前の和集合の違いだけを調べる。二世代前側の集合・記述子数が実転送記録57世代と一致することを確認した。重い530～570世代では、一世代前との集合は平均484.683byte、費用523.049byte相当だけ少ない。世代546は11744byte/41個から10176byte/36個へ減る。

これは前面一括更新が常に選べると仮定した静的な集合比較で、ゲーム実装・速度測定ではない。過去のadaptive-vramは準備費用で退行しているため、そのまま繰り返さない。固定mapで行う場合も、各VRAM面が実際に持つ世代の占有mask、分割中の面の所有権、準備するCPUと時期を管理する必要がある。表示中の面への分割転送は許可できない。まず追加準備費と節約量を比較してから実装を判断する。

## 保存

commands.jsonが引数列、comparison.jsonが集計、evidence.zipがROM・生成source・labels/map・Lua・全バッファ・VRAM/PPU/RGB・転送記録・検証結果。初回宛先版の費用57対照は、現在の同じflagだけでは同じROMにならないことをcommandsにも明記した。実際のROMと生成source、ca65引数を保存し、再現できると偽らない。

Pythonはbundled 3.12。各Mesen試験とホストの画素検証が端末で終了してから次のROMへ進んだ。公開ROM9934d77bは維持する。通常buildへの復元とsmokeの結果はdefault_restore.jsonへ保存する。全ゲーム・全武器・敗北までの4000フィールド監査は未完了で、goalはactiveのまま。
