# 爆発の幅91追加・右端限定・内部RAM実行

60fps未達。既存の全素材・全1,492寸法を維持し、前回の幅94に加えて爆発40/41の幅91・高さ71をstack描画の対象にした。通常クロック・同じ入力・道中800フィールドで比較した。公開ROMは変更していない。

| 方式 | ロジック / 表示 | 画素一致 | 2フィールド間隔 | 最大SA-1時間 |
|---|---:|---:|---:|---:|
| 幅94/91を対象 | 654 / 643 | 168 | 6 | 24.074ms |
| 右端で切れる物だけ | 655 / 644 | 168 | 5 | 23.312ms |
| 右端限定＋helperを内部RAMへ | 655 / 644 | 168 | 5 | 23.312ms |

全件で実PPUの参照先を確認し、転送済みVRAM・完成FB・同一世代packetを照合した。幅94のみの前回は644表示・5待ち、比較元BW配置表版は645表示・4待ち。この三方式の採用だけでは改善しない。表示数には起動準備も含むため800で割ってfpsとはしない。

同じ幅91・高さ71・asset41・中心x255・bottom201の右端爆発は、比較元5.462ms、追加版3.604ms、右端限定3.595ms、内部RAM版3.519ms。一方、画面内に収まる中心x182・bottom191の同じ爆発は比較元1.549msに対して無条件のstack描画4.454msとなった。rowごとの設定費用があり、PEAを使えば常に速いわけではない。右端限定でこの悪化を避けても、非対象寸法と他の準備・転送費用が残る。値はIRQや共有バスの影響も含む実ゲーム内の経過時間。

幅91追加版は613共有record・54,752byte。圧縮したleft hintの直後7DB3C0..7DFFFFと、以前のhintが置かれていた7EB000..7EC3FFを追加で使用する。7E0000..7EAFFFは予約のまま。配置前に全零を確認し、元の全寸法は保持する。613 kernel・21,315右端byte境界の静的画素比較が一致した。

内部RAM版はhelper原本を03:E400へ置き、実行時だけ0300から522byteへコピーする。既存worker0200..02D5と転送作業域05C0より下の間に収まることをリンク後に検査する。SA-1 DMAを使える場合はDMA、PPU転送要求中はMVNでコピーする。対象外の画像は従来のnative描画へ戻す。

境界試験は幅94・高さ73/74と幅91・高さ71、横13位置、上端・中段・下端の7位置を循環する。右端限定版・内部RAM版それぞれ700フィールド、548表示を全画素照合し、末尾停止0。限定fixtureの毎フィールド表示をゲーム全体の60fps達成とは扱わない。

右端限定版の初回host画素照合はPythonの `ValueError: generator already executing` で終了した。エミュレータは700フィールドを完走していたため、同じ保存済み548画面・同じROM/labelへ同じ画素検査を再実行し、全件一致を確認した。検査条件は変更していない。初回ログと再実行script/logを証拠ZIPへ保存した。内部RAM版の照合は通常runnerで完了した。

各コマンドはcommands.json、ROM SHA・表示間隔等はcomparison.json、元ROM/LBL/MAP・画素・VRAM・packet・ログはevidence.zipへ保存した。

次は、stackを描画先へ切り替える処理を省き、右端の隠れた命令を飛ばせる逆順STA行コードを検討する。追加コピー方式では幅94だけでも45,465byte、幅94/91で81,444byte必要となり、二幅の追加は空き容量を超える。1,104行コード・38,662右端byte境界は元コードと静的画素一致。`reverse_explosions_capacity.json` と同verified.jsonは容量・静的比較でありゲーム速度の証拠ではない。元のnative行コード自体を対象寸法だけ逆順へ置き換えれば、全描画のfallbackを保ったまま二重保持を避けられる可能性がある。ゲームへの統合は未実装・未検証。
