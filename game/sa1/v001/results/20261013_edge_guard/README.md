# 画面端の退避経路・JIT読み込み・cache容量の比較

60fpsは未達。元の4bpp素材、全縮小寸法、物量、ゲーム時計、通常クロックを維持して実SA-1の統合ROMを比較した。公開ROMは更新していない。

## 変更と測定

右端の爆発41（94×74、job429）は、基準版では5分割の退避・復元だけで約4.140msを使っていた。専用コピーコードを使う幅32byte以下では、DMAが空いていてもCPUコピーを強制していたため、`--edge-dma-min`で切り替え幅を比較した。PPUの変換が使用中の場合は従来通りCPUへ退避する。

`--edge-lazy-jit`は、幅・offset・chunk長の決定を先に行い、内部RAMへ512byteのコードを読み込む処理だけを最初のCPUコピーまで遅らせる。全chunkをDMAで処理できた物体は読み込まない。最初のCPUコピーでのロードとbank補正が終わるまで実行しない。

`--edge-band-guard`は、既存の8行単位のalpha帯表から現在のchunkの右端を求め、爆発40/41の退避幅を狭める。左端・反転・元の退避幅32byte超は従来経路。chunk長と512byte上限を保持し、幅が変わった時だけコピーコードを再ロードする。77chunkでコピー幅が縮み、片道の総退避量は110828→105252byte。しかし判定費用が勝ち、重い区間の平均とボス表示が退行した。v2では不要なhelper呼出しを省いたが表示改善はなかった。

`--edge-jit-max 12`は、12byte以下だけ専用コードと512byte退避領域を使う。幅が広い場合は専用コードを使わず、元の1024byte退避領域とchunk長へ戻す。DMAが空いていればDMA、変換中はMVNを使う。退避がコード領域0500..06ffを上書きしても、広い退避の途中ではそのコードを実行しない。次の小さい退避は必ず再ロードする。この版ではjob429が4分割・約2.591msへ短縮した。

## 道中800フィールド

全7方式で647枚表示、初期2枚を除く表示間隔は1フィールド640回・2フィールド4回。168画面の元画像・VRAM・実PPU・RGB照合を通過。各方式と基準との共通653世代で、全24576byte描画バッファ、packet、転送集合、消去端が完全一致した。

平均は同一packetの重い41世代（530..570）。基準には前回の座標変換短縮と近景packedコピーを含む。

## 独立検証と限界

広い退避を1024byteへ戻した版は、ボス1900フィールドで1747枚表示、表示間隔1=1741回・2=3回。最大SA-1は18.623222ms、最大出力準備完了20.183662ms。基準の1747枚・3回待ちと同じで、最大時間は少し遅い。147画面の独立した画素照合と、共通1752世代の全バッファ・packet、1753回の転送集合・消去端の一致を確認した。

さらに爆発40/41の3寸法（94×73、94×74、91×71）、左右13位置、上下7位置を組み合わせたfixtureを実行。450フィールド・300枚表示・300画面の全画素照合が合格。退避量の最大は924byte、512byte超のchunkは660回。DMA1931回・JIT332回・MVN85回を通る。これはpacketを試験内容に置き換えており、ゲーム全体の60fps証拠にはしない。

専用コードの実行直前に512byte全部とbank補正箇所を毎回照合した。1024byte版の道中1584回、ボス2108回で合格。bank40..43、幅2/4/6/8/10/12を通る。道中ではDMA222回、JIT1584回、MVN14回の退避・復元を実行。cache容量のassertも追加した。全1492寸法・native90854行・弾158688行を以前のROMと比較し、5992縦位相dirty表を元画像から独立再計算した。

残る道中の表示待ちはfield692/696/699/702。IRQ終了時点の描画済みキューは3/3/3/4枚あり、描画を待ってキューが空になった状態ではない。描画短縮だけでは待ちが消えず、転送・表示側の期限も引き続き調べる必要がある。

## 再現と保存

`commands.json`に各buildのargv、`comparison.json`にROM SHA・全指標・比較数を保存。`tools/report_sa1_edge_guard.py`で比較を再生成できる。Luaを読み込んだMesenとPythonの全画素検証が正常終了してから次のROMへ切り替えた。

`evidence.zip`は60,570,284byte、SHA-256 `ed7c4e481d44eb84b02fc7b6a9ab3334e813779273a26ae62ca8400b566bce73`。7候補ROM、Lua、labels/map、全バッファ、packet、VRAM/PPU/RGB、転送・退避・JITログ、元画像独立検証結果を収録した。

alpha帯v1とv2は同じflagでもhelper実装が異なる。v1のROMとhelper sourceはsnapshotが正本。現在のsourceでv1のROMがbyte同一に再生成されるとは主張しない。

最初の1024byte版の道中は画素検証を通過したが、計測ログのmode文字列をJSONで引用していなかった。ログ生成を直し、同一ROMで800フィールドを最初から再実行したv2を比較に使用。最初のLua・ログ・summaryも証拠へ保存した。

全変更はopt-in。今回の候補を60fps達成版として公開していない。

最後に通常buildを再生成し、基準SHA `a9bcd2478e39f479b641ededc38d77abe4e693d2b958d1bd7b4f7ab20af603f7`への一致と、130枚表示・120画面照合のsmoke正常終了を確認した（`default_restore.json`）。公開ROMのSHA `9934d77b85913187be8d3ebd8315f854718eb24b08492204ce8b3288f620146c`も保持している。
