# 配置表をS-CPUへ移しても改善しない

SA-1は次画面の描画を開始し、その間にS-CPUが前画面の1472B配置表をWRAMへ作る。可変長CHR FIFOと素材は維持し、表の完成フラグで表示切替を制限する。前画面の表をBW-RAMからCPU DMAで退避する工程は省いた。

|方式|800フィールド中のlogic/表示|2フィールド間隔|画素一致|
|---|---:|---:|---:|
|公開固定map版（既存比較）|654/647|4|168|
|SA-1の融合map付きFIFO（既存比較）|653/642|6|168|
|CPUでmap初期化・記入|619/614|34|168|
|map初期化のみDMA、記入はCPU|643/632|16|168|

正常な2試験では、実際のPPU参照先から復元した画素、native背景・プレイヤーを含む検査、および共通logic世代の描画packetが一致した。CPUの仕事が増え、SA-1と並行させても処理全体は遅くなる。公開ROMを変更しない。60fpsは未達。

表の1472B初期化を通常のCPU書込みからROM→WRAM DMAへ変更すると改善するが、既存方式に及ばない。初期失敗3件は比較から除き、原因をcomparison.jsonへ記録した。成功ROMとラベル・実測証拠をevidence.zipへ保存した。

左右・上下反転を同一キーとして扱った理想LRUの試算も保存した。負荷集中41画面で512タイル容量は8335要求中7916ミス（94.97%）。1536タイルでも7744ミス（92.91%）。表示中・転送待ちのタイル保護、ハッシュ生成、比較、再配置、DMA設定の費用を含まない楽観的試算であり、実装による速度改善を示すものではない。
