# 左右clip helperのI-RAM再利用と遮蔽の上限

60fps維持は未達。素材・全1,492寸法・通常クロックを保持する独立SA-1分岐で比較した。配布ROMは更新しない。

--clip-residentは、0300..04FFに残る左端helper・逆順右端helperの再コピーを省く比較用のopt-in。07FCのtagで種類を区別し、各フレームのclear開始、stack clearの準備、弾workerのコピー、大きな画面端退避で無効化する。helperの両サイズが0200以下であることを検査し、0500からの小さいedge JITと重ねない。既存bullet residentの019Cとは別に管理する。

全試験で共通logic世代のpacketが配布固定map版と一致し、末尾停止なし。初期2枚を除いて表示間隔を数える。道中のログは左cache hit9回、左miss59回、右miss10回、右hitなし。再利用できる機会が少なく、表示遅れの改善につながらなかった。ボスも3フィールド間隔が発生し、採用しない。

専用fixtureは左端の爆発を連続させ、弾、大きな端の退避、左右helper切替を挟む。最終試験は706フィールド・240表示で全画素一致、実PPU状態・表示VRAM・paletteも照合した。左hit240/miss720、右hit239/miss240。弾と大きなedgeによる有効helperの破棄も各240回あり、上書きなしの連続実行だけを試したものではない。cacheの回数は実行点のログとして数え、表示枚数との比率を速度改善の根拠にはしない。

最初は最大600フィールドで試し、240表示の目標へ届かず194画面で終了した。これを240画面合格の根拠にしない。上限を1000フィールドへ延ばして上記240表示を確認し、初回ログは別枠で保存した。fixture自体は意図的に8物体を重ねた正しさの検査で、最大36.957394msとなる。このfixtureを60fps達成の証拠には使わない。

静的に全1,492寸法、native行90,854回、弾の行158,688回、右端1,557kernel/59,519境界、左端6,326kernel/190,929ケースを元ROMと照合した。flagを外して再ビルドすると従来v5のROM SHA 7124eab2f29ffca6904f68d1c7ee705933dd0b341bbb0082db9366468fc4a7fbへ完全に戻ることも確認した。現在buildはこのflag OFF版。公開ROMのSHAは9934d77b85913187be8d3ebd8315f854718eb24b08492204ce8b3288f620146cのまま。

## 奥に隠れた描画の解析

既存の配布固定map版から、負荷集中の連続41画面（世代530..570）のpacketとFBを使用した。各spriteを元絵と同じ縮小・反転で独立に合成し、最終sprite画素が保存FBと一致することを確認する。nativeの4画素wordはspriteの左byteを基準にし、画面x=0に固定した誤った区切りを使わない。

全454,780描画画素のうち、後から描く物体に隠れるものは84,326（18.54%）。nativeの有効word126,381のうち、非透明画素が全て隠れるwordは21,292（16.85%）。これは遮蔽判定・情報生成・分割描画の費用を除く楽観的な上限で、速度短縮率やROMでの実装結果ではない。

行全体が隠れる部分に限定すると省けるwordは4,705（3.72%）。さらに手前の爆発39/40/41の最大不透明矩形だけで奥の行を安全に隠せるものは71word（0.056%）。最大矩形の内部が全て不透明であることも検査する。矩形単位や行全体を省く実装だけで大幅改善する根拠は得られなかった。4画素単位で省く場合の実行費用は未測定。

集計はcomparison.json、遮蔽の全数はocclusion_feasibility.jsonとopaque_rect_feasibility.json。再現はcommands.jsonおよびtools/analyze_sa1_occlusion.py、tools/analyze_sa1_opaque_rects.py。証拠zipへROM・labels・manifest・静的検証・全画素照合データと解析入力41画面を収録した。
