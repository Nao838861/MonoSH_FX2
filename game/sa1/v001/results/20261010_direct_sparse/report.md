# ゲーム処理分離と三面への直接疎転送

ゲーム全体の60fpsは未達。原素材・縮小・色・輪郭は維持し、通常クロックのMesenで実行した。配布ROMは変更していない。

## ゲーム処理の分離

`--sa1-game` はBW40の64KBへ初期状態を複製し、ゲーム処理をSA-1 IRQで実行する。本体側の入力を渡し、packet・自機OBJ・背景の位相・音イベントだけ戻す。workerのDPを保存し、cc65のDPとhardware stackをゲーム用へ切り替える。元のゲームと同じコードを再アセンブルし、WRAM7Fの不変表への参照はROM C1へ変更する。地面表は本体CPUが作る。raw面はBW41/42の上下と43の上の五面とし、BW40とは重ねない。

800field/669枚・129画面一致。本体側の所要時間は減ったが、ゲーム更新がSA-1の描画を中断するため、全体は悪化した。`--game-stage-overlap` で本体の文字変換と重ねても669枚で改善しない。

並行版の最初のソート照合は、本体CPU側からBW-RAMを読み、CC type1変換中のデータを検査していた。SA-1自身のメモリ空間から生データを読むよう検証器を修正し、安定ソートの内容を維持したまま再照合した。これは成功条件を緩める変更ではない。

## 必要な文字を直接VRAMへ送る

`--direct-sparse --vram-prefetch3` はSA-1で疎タイルの位置表を作り、元raw画像からCC type1で必要な文字をVRAMへ直接並べる。SA-1での詰め直しと、本体CPUによるWRAMへの中間コピーを省く。mapだけ最後にCCを無効にして生データで送る。透明文字128番は初期化時のゼロを保持する。上限383文字を超えたら停止し、画像を省略して続けない。

800field/701枚・129画面一致。表示間隔2fieldは10回で、生成541〜550に集中する。描画済み画像が3〜5枚待っているので、この区間は転送が主因である。

`--unroll-ppu-dma --bottom-slack` を加えた版は702枚・129画面一致、間隔2fieldは9回。展開DMAはCHRの記述子だけを処理し、最後のmapを別に送る。コード領域が122B不足したため、不変のDMA入口表150BをGSU ROMへ移した。本体のCODE bankを越えるコードや表は作らない。

実測した記述子ごとの費用は、ループ版の約620master clocksから展開版の約470master clocksへ減った。しかし大きい画像が一括転送の予算へ収まらない場合、部分転送の遅い経路が残る。次は部分転送でも、収まる複数の記述子をまとめて展開DMAへ渡す。

正確なROMハッシュ・フラグ・表示間隔・元rawと最終VRAM/OAM/CGRAM/地面の照合証拠は `index.json` と `measurements.zip` に保存する。
