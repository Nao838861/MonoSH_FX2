# 転送要求時期・収集時期・部分転送予算の検証

60fpsは未達。元の1492縮小パターン、画素、ゲーム進行、非表示区間を維持した6構成を比較した。最良でも道中の表示待ち3回、ボスの2回が残り、既定版には採用しない。公開ROMも変更していない。

## ゲーム内の比較

道中は800フィールド、各168表示を元画像・FB・VRAM・実PPU・RGBへ照合した。共通653世代以上の24576B全FB、packet、占有mask、消去端も基準full192と一致した。表の「待ち」は更新間隔が2フィールドだった回数で、起動時間を含む総フィールド数から平均fpsを算出した値ではない。

|構成|表示数|2フィールド間隔|最大SA-1時間 ms|
|---|---:|---:|---:|
|基準full192、DMA計測付き|648|3|21.494164|
|次の転送候補がある時だけ二度目のmetadata収集を延期|647|4|21.475726|
|上記＋宛先事前計算・短いI/O・16展開・末尾予約1400|648|3|21.416966|
|転送要求IRQを197→190行へ移動|647|4|21.583561|

最後の構成のボス試験は1900フィールド・1748表示、2フィールド間隔2回、最大18.492386ms。147枚の画面照合と基準との共通世代比較を通過した。画面内の転送待ちをSA-1描画時間だけから判断しない。

収集延期は最初のIRQ収集を維持し、二度目の収集だけを条件付きで省く。完了未回収の状態で省けたのは道中3回だけだった。先行IRQの二段構成も改善なし。196行版は遅延経路654回、実到達行197/198/200を検証した。実blank開始203行、解除22行、HDMAの13B表は全構成で維持した。

## 部分転送と不合格ROM

全量転送・表示切替の予約は維持し、全量が入らない場合だけ小さい予約でprefixを選ぶ。最後の記述子を必ず残すため、増やした予算で表示切替まで進むことはない。最後の1024B以下かつCHR更新なしの場合だけ従来試作の予約1400を使う。

転送負荷fixtureでは500フィールド中153表示、全153画面一致。前回tail16の144表示から増えたが、更新間隔は2～3フィールドで60fpsではない。prefix460回、途中記述子の再開60回、最大部分1248B。fixtureはSA-1自身が元爆発40/41を9個描画する。ホストはpacketを設定するだけで描画代行しない。

初期の部分予算版には、`pipe_time_left`の期限超過returnで前回のraw予算が残るバグがあった。旧tail版SHA `5668da59d649d520af70b0fcbaa5b00d15af3f3e849cb7b1c369817db0618f65`を同じSHAで再生成し、field697/line25/masterClock249118568の非blank DMA開始を再現した。毎回冒頭でraw予算をゼロ化し、現在の静的検証はこの旧ROMを拒否する。修正版SHA `2a276ed8eaf290beb7f210d14ee1ae90439284631903036a3dc3e2c7abeae827`は道中・ボス・fixtureを再実行した。

`historical_*`の部分予約1300/900/900-tail初期版は同じ欠陥を持つため、画面照合が通った試験も性能候補から隔離した。保存された旧静的検査は今回のゼロ化条件を含まない。初回collect試験はharnessのexport不足で失敗しており、修正後のv2だけを比較した。Mesen停止要求後にもcallbackが進む場合があったため、検査側は最初の異常と状態を保持するよう修正した。

## 実DMA時間

基準と同じROM SHA `f685de707b32c4390b49cadf2ed51b05da446ed331eaa74421d499d59f4a9c4f`でSTY $420B直前とDMA後の命令位置を計測した。ROMのブロック先頭・末尾命令と23/26B幅も静的検証する。

1400個のDMA sampleから、開始・終了の揃う80転送groupを再構成し、独立prefix選択の個数・byte数・世代と一致させた。計測窓末尾で終了を失った1groupは除外した。NMIでfieldカウンタがgroup途中に変わるため、masterClockで所属を判定した。

group全体の実測と現在の費用式との差は−994～＋1228 master tick。重い世代543/546/549はそれぞれ−538/−226/−152 tickだった一方、小さいgroupでは＋1000 tick程度もある。個別sampleの超過時間にはI/O設定全体が入らず、groupには設定・NMI・HDMA・refresh等が含まれる。一律に費用を減らす根拠にはしない。

低位2plane/高位2planeの別転送も元FBから上限だけ調べた。重い530～570世代の平均削減は429.268B/世代、543/546/549は144/128/208Bに留まる。48記述子制限のためgapを広げた結果で、比較処理やCC1配置の費用は含まない。実装済み改善とは扱わない。

## 検証・成果物

- 実ROM命令による探索59024条件、全量判定58148条件、予算262144条件、Y復元、blank表を検証。最新の部分予算版では冒頭ゼロ化も確認し、旧ROMの拒否結果を保存。
- 元1492パターン・native90854行・弾158688行と基準画像の一致、元alphaから独立したdirty5992縦位相表の一致を確認。
- `comparison.json`は集計、`commands.json`は現行build引数。旧source変更を現行flagで同一SHAに再現できるとは主張しない。
- `evidence.zip`はROM・生成source・labels/map・Lua・全FB/VRAM/実PPU/RGB・転送ログ・検証結果・初期不合格資料。CRC検証済み。SHAと容量はcomparisonを参照。
- `default_restore.json`は通常構成への復元と280フィールドのsmoke結果。ユーザーが起動しているMesenには触れていない。

次は同じ予約値や要求時期の微調整を繰り返さず、残った待ち世代の転送構造と再利用可能な素材単位を調べる。OAMや走査線上限、描画順、縮小・元画素の保持を満たす必要がある。全ゲーム・全武器・敗北経路の長時間検証も未完了。
