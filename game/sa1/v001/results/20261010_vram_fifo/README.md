# 可変長VRAM保持の実測

固定配置版と同じ絵・寸法・ゲーム処理を使い、BC20未満のVRAMを可変長のFIFOとして割り当てた。空タイルを各8KiB境界に予約し、BG1の32KiB参照窓へ収める。元のBW面と配置表の寿命を分ける退避方式も実装した。

全件800フィールド、168画面の画素一致と実PPU参照位置、非表示期間のDMAを検証した。固定配置版との描画packetも共通世代まで一致する。

| 試作 | 表示枚数 | 2フィールド間隔 |
|---|---:|---:|
| 可変長配置、配置表を元BW面に保持 | 638 | 11 |
| 配置表をWRAMへ退避 | 638 | 10 |
| 定数時間割当・記述子のコピー省略 | 641 | 7 |
| 配置表と転送区間の生成を統合 | 642 | 6 |
| 完成画面11枚を先行保持 | 639 | 6 |
| 統合生成、WRAM退避なし | 642 | 8 |

保持できる画面数は増えたが、配置表の生成・退避が増えた。負荷集中時にはSA-1の描画済みキューが空になる。最良の固定配置版647表示・待ち4回を超えていないため、公開ROMへは採用しない。開始時刻が異なるため、表示枚数だけをfps換算しない。60fps維持は未達。

`check_sa1_fifo_allocator.py` は開始位置1505通り×サイズ352通りの529,760入力で、定数時間計算を一タイルずつ進める参照計算と照合する。実機命令そのもののエミュレーションではなく、配置計算の補助検証である。

初期版の配置表境界判定でbit10が衝突する不具合は修正した。次の検証ではチェック側が64KiBの実VRAMアドレス折返しを見落としていたため、PPUと同じ折返しを実装し、同じROMをfifo_v3として再検証した。初期二件は速度比較の証拠に使わない。

再現コマンドはcommands.json、集計はcomparison.json、採取画面・実PPU状態・記録・最後の試作ROMはevidence.zip。公開ROMは9934d77b85913187be8d3ebd8315f854718eb24b08492204ce8b3288f620146cを維持する。
