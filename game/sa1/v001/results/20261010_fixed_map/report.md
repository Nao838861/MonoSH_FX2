# 固定タイル配置表による転送削減（2026-10-10）

**60fpsは未達。素材・描画世代を維持し、実際の表示間隔を測定した途中結果。**

既存の4bpp画像とパレットを変更せず、BG1の配置表を固定した。毎フレーム1,472Bの配置表転送とSA-1での表生成を省く。VRAMのCHRは24KiBの二面を使い、同じ面に残る二世代前の占有範囲も更新する。透明になった場所も送るため消し残しを防ぐ。元から表示窓外の先頭8行だけは従来通り送らない。

VRAMのbyteアドレスはCHR面0000/6000、BG1配置表BC00（使用部分BC40..C1FF）、遠景の配置表C200/CA00、自機C400..C77F。遠景64tile・草62tileは空き領域へ移し、地面D000..E8EFと地面配置表F000..FFFFを保持する。OBJの番号と転送先を同時に変更し、画像そのものは変えない。

圧縮したPPU起動画像を展開する版は起動が約60field長い。表示総数だけで速度を比較しない。同じlogic世代に同じ入力を注入し、従来版と描画命令1,749世代分が完全一致した。ボスの変更前後も1,745世代分一致。Mesen通常クロックで、VRAM・遠景・近景の合成・地面・OAM・パレット・実際のDMA非表示期間・IRQとゲームの演算器競合を検査した。

事前hintのない大きな絵を左端から直接描く `--left-runtime-scan` も試した。15,566kernel・474,877位置で静的画素照合、Mesenの専用320世代で123画面一致。しかし道中の遅れは9回のままで、爆発の一部は遅くなるため試遊版には採用しない。

`--redraw-no-history` は全再描画時に参照しない旧packetコピーを省く。消去範囲の履歴は維持する。`--bullet-resident` は連続する敵弾だけ内部RAMの描画コードを再利用し、フレーム先頭と他の絵の描画前に無効化する。色・反転・縮小・四辺クリップの専用テストも120画面一致。

従来版を同じ入力で再測定した初回はfield669/line22に非表示時間外DMAとなった。失敗として証跡に含め、速度比較から除外した。期限2行確保版で測り直した結果だけを表に載せた。
