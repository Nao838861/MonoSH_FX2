# 木の左端prefixと表示待ちの切り分け

60fps未達。元の全44素材・1492寸法・色・物量・通常クロックを維持して比較した。新経路は既定OFF。公開ROM9934d77bは保持する。

木4の逆順native行で、左側の画面外コードを省き、可視prefixだけをIRAM0700へコピーする経路を実装した。同じコード・clip位置の連続行は物体内で再利用する。転送許可が得られる場合はSA-1 DMA、PPUの変換転送と競合する場合はCPUのMVNを使う。奇数位置で前行の1byteへ触れる分は保存・復元する。コピー内容とRTL、guardの復元を実行中に検査した。

v2と無効比較の全runtime labelsは同じで、ROM差分は制御命令6B＋checksum4Bだけ。再利用なし比較は制御JMPの1byte＋checksum2Bだけ。**22回の待ちは、左端経路を無効にしても変わらない。前段の23回から減ったことを、この高速化の効果とは判断しない。** 既定には採用しない。

個別の66×152・左端の木は、v2で9.108ms、再利用なし10.674ms、無効9.611ms。全幅v1では7.865msまで短縮するが、小さな欠け方の物体が遅くなり、全体は悪化した。v2は1065行のprefixを850回コピーし215回再利用、コピー総量18792B。コピーなし比較は25266B。patch_completeとbuffer_readyは同じ機械語位置なので、前者のイベント数をコピー回数として数えない。

全76寸法・9336行使用・5751kernel、右90588byte境界と左84838byte境界を任意下地のmask/valueで照合した。v1/v2とも左右12位置×上下3位置の2736ケース、1369実PPU画面が一致した。通常試験は各版とも基準との3831世代以上の全framebuffer・packet・tile mask・消去端と完了ゲーム状態が一致。限定fixtureをゲーム全体60fpsの証拠にはしない。

## 実際の非表示期間の入口と出口

前段基準34226b26を同じ4000field入力で再測定し、3828表示・23待ち・181画面一致・最大24.084716msを再現した。HDMAが実際に非表示にする202行、表示を再開する21行でキュー状態を記録した。最初の2表示後の判定で、表示番号が増えない区間は既存の23回と一致した。

18回は、非表示開始時にready=0・rendering=1・転送対象なしで、次の表示開始でも転送対象なしだった。そのうち15回は表示開始時にはready=1になっていた。残る5回は同じ転送対象が非表示開始から次の表示開始まで残っていた。うち3回は後続readyが3枚あり、2回は後続readyが0枚。全23回で転送完了キューは空だった。

これは入口・出口の状態分類であり、18回全ての原因を描画だけと断定する計測ではない。途中の完成時刻・collect・IRQ待ちも関係する。5回も転送対象が残ることまでは確認できるが、帯域と開始遅れの寄与はここだけでは分離できない。slotの世代番号はこのobserverでは採取していない。二面の裏面へ次世代を先行転送する仕組みは既にあるため、単に「flip後も転送する」を新案として再実装しない。
