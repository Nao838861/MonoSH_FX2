# 投影表をWRAMへ戻す比較

配置表専用BW-RAM版では7FA000以降をmap退避に使わないため、投影表をWRAMへ戻せる。FIFOのビルド条件をこの構成だけ緩め、CPU CODEのrun=0・size<=10000を検査した。実CODEはFFC2（65,474B）で64KiB以内。

800fieldで656logic/645表示、2fieldの待ち4回、最大SA-1時間22.330117ms。168画面が実PPU参照から一致し、同じ入力のsprite packetも共通世代まで一致した。元のBW配置表版と表示数・待ちは同じで、公開ROMは更新していない。60fpsは未達。

空いたROM28,638Bへ爆発39/40/41の左端hintを追加する容量も測定した。39だけで追加hint36,666B、hash占有7,202/8,192。40までで9,334件、41までで11,599件となり現在のhashに収まらない。全三種の追加hintは88,415Bとなるため、そのままの拡張は実装していない。`left_hint_capacity.json` は容量だけの測定で、速度改善の証拠ではない。

次の候補は、本体CPUが次画面の占有範囲を計算している間にSA-1が前画面を描く構成。現在はSA-1が描画前に占有範囲・shape pointerを計算しており、重い画面で3〜4msを占める。全体の処理時間と画素一致を実測するまで採用しない。
