# S-CPUで前面差分リストを作る費用の検証

60fpsは未達。前面へ一括更新すると仮定した`current|prev1`の転送集合は小さくなるが、今回のS-CPU実装では準備時間が削減分を大きく上回った。表示方式への採用は見送る。

| 世代 | 前面集合の転送量 | 裏面集合からの削減 | S-CPU準備の実測 | 削減できるDMA費用の時間換算（見積もり） |
|---|---:|---:|---:|---:|
| 543 | 10,048 B | 352 B | 8.788174 ms | 0.157189 ms |
| 546 | 10,176 B | 1,568 B | 8.515327 ms | 0.711822 ms |
| 549 | 10,944 B | 704 B | 9.690337 ms | 0.209710 ms |

右端は累積費用式`n+n/32+n/128+57`の差を8 master clocks/単位で換算したもの。転送時間差の実測ではない。S-CPU準備はコピー・リスト構築・累積表作成・履歴保存を含む。SA-1へ同じ処理を移した場合の速度は、この結果から達成扱いしない。

## 方法と照合

`--fixed-front-probe --fixed-front-probe-generation <世代>`を既存full192版へ加える。指定世代だけS-CPUがBW-RAMから現在と一世代前の占有マスクをコピーし、最大48個の転送記述子と累積費用表を作る。実際の前面VRAM更新は行わない。処理末尾で計測用エミュレータを終了し、遅い診断処理が以降の表示へ与える影響を測定結果に混ぜない。

Lua側は占有範囲取得時の履歴とマスクコピー、各記述子の長さ・転送元・転送先、累積byte数・費用、CPUレジスタとスタックの復元を独立検査する。元のROMとそれぞれ543・546・549世代の24,576 B全フレームバッファ・描画命令・占有マスク・消去端が一致。計測直前までの134・138・142表示は原画・VRAM・実PPU設定・RGBの照合に合格した。

各ROMで既存の探索59,024条件、全量判定58,148条件、走査線・水平位置262,144条件、Y復元、blank HDMA表のCODE内配置を再検証した。

## 失敗した試作

最初のROMは存在しない81:xxxxミラーを呼び出した。次の2本はC2の起動コピーの前提を壊した。RODATAを先頭に置くだけでは不十分で、RODATA後のゼロ余白がBSS初期化にも使われている。最終版は追加処理を実際の01:xxxxのROM領域へ配置した。

連続実行版は215世代分のリスト照合を通ったが、field384・line27の表示中のページ切替で既存検査が停止した。正常表示や60fpsの証拠には使わない。現在のビルドは単発の世代指定を必須とし、連続版は証拠用ROMとしてのみ保存する。

- `evidence.zip`: 最終3本と失敗した連続版のROM、当時の生成ソース・labels・map、Lua、全フレームバッファ、VRAM、PPU/RGB、転送履歴、独立検証。
