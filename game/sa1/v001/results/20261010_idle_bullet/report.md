# 先行消去・敵弾の端処理・連続CHR転送

全体60fpsは未達。元の4bpp素材、縮小参照位置、色、透明形状を維持し、通常クロックのSA-1と本体CPUで計測した。公開ROMは更新していない。

## 描画側

空いたraw面をSA-1の待機時間にDMAで消す `--idle-clear` を追加した。本体CPUが7面それぞれの所有権をBW-RAMへ公開し、SA-1は転送終了済みの面だけを消す。履歴を空にするのは実際の消去が済んでから。800fieldの平均消去時間は約1.5msから0.4msに減ったが、重い場面の連続描画中は待機時間が少ない。1,800fieldの表示は1,681枚から1,682枚になっただけで、単独では解決しない。

左端にはみ出した敵弾は、端の不完全なwordを処理し終えても残り全体を遅いループで描いていた。`--bullet-left-fast` で画面内の残りを高速ループへ戻す。さらに `--bullet-opacity` は既存の圧縮行ヘッダの2Bを、不透明な4画素wordの事前判定へ置き換える。元の画素データは同一で、16wordを超える部分は通常のマスク処理へ戻る。色、反転、寸法、四辺の切り抜き120画面を独立合成と照合した。

## 転送側

`--sparse-merge-gap 32/64` で小さな透明区間も一緒に送りDMA開始回数を減らしたが、800fieldの表示枚数は704枚のままだった。

疎タイル転送先のCHRは連続するため、`--contiguous-chr-dma` でまとまりの先頭だけVRAM転送先を設定する。途中で転送が途切れた場合は、再開するまとまりの先頭で設定し直す。生のmapは別に転送先を設定し、キャラクタ変換を停止する。先行消去・敵弾の改善と併用した1,800field試験は1,689枚、146画面一致。表示間隔2fieldが22回残るため60fps達成とは扱わない。

部分転送の区間選択は、従来の線形走査で平均約1ms、最大約1.9msかかっていた。SA-1で累積費用表を作る案は二分探索を約0.3msにしたが描画側へ負担を移す。`--prefix-cpu-table` では収集済みWRAMの記述子から本体CPUが事前に表を作り、追加のSA-1処理とBW-RAM転送を避ける。除算器を修正した版は800field/701枚・129画面一致で、現在の本体CPU処理では余裕が足りない。既定には採用しない。

dirty矩形の計算とマスクをI-RAMへ移す案も併用し、修正後の費用表版ではSA-1最大21.664msだった。描画時間が減っても表示間隔は改善しないため、描画時間の平均だけで成功を判定しない。

## 除算器の競合修正

初期の費用表版は割り込み中に本体CPUの除算器を使っていた。中断されたゲーム処理とレジスタが競合する可能性があるため、6で割る計算をROMの表引きへ変更した。検証器は本体IRQ内から4202..4206へ書いた時点で失敗する。修正前の費用表試験は画素一致の記録を残すが、速度の比較には採用せず `performanceComparisonEligible: false` とした。描画画像の一致だけではゲーム処理との非競合を証明できない。

条件、ROMハッシュ、表示間隔、原packet、raw画像、実VRAM/OAM/CGRAM、DMAログ、先行消去ログは `index.json` と `measurements.zip` に保存する。最終目標は完了扱いにせず、描画と転送の改善を継続する。
