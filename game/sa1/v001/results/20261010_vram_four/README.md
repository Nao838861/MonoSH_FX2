# 4面CHRと共有マップの試験

`--vram-four-shared`でCHRをbyte 0000/3000/6000/9000の4面に分ける。
各面はtile0を透明、tile1..351を動的描画に使い、CHRを連続転送できる。
遠景64tileは8C00..8FFFとBC00..BFFFへ移し、BG2のCHR baseを8000とする。
近景・地面・自機の素材と配置は維持する。

BG1のマップはC000で共有する。描画済みCHRを最大3枚まで先行転送し、
表示する世代のマップ736wordを切替時に生BWからC040へ送る。
元の全描画命令と表示順を保ち、コピー途上の画像は表示しない。
v2は自機画像が変わる場合の展開DMA経路にも、mapの追加費用を予約する。

| 試験 | field | 表示枚数 | 画素照合 |
|---|---:|---:|---:|
| v1 道中 | 800 | 704 | 129 |
| v1 道中・長区間 | 1,800 | 1,688 | 146 |
| v2 道中・長区間 | 1,800 | 1,688 | 146 |
| v2 ボス・長区間 | 1,800 | 1,676 | 145 |
| v2 反転・縮小・色・四辺fixture | 232 | 120 | 120 |

道中の既存最良1,689枚を超えないため公開ROMへは採用せず、60fps未達とする。
351tile容量はこの区間を通過したが、全ゲームで足りるとの結論ではない。

CPU関数の経過時間にはIRQ処理が混ざるため、従来値を残して`activeLogicMs`と
`activeParts`を追加した。道中の純CPU平均11.135ms・最大13.481ms、
ボスは平均10.391ms・最大21.843ms（最初の準備を含む）。
ボスの重い通常場面では描画命令の準備が約5msあり、これを次の最適化候補とする。
SA-1描画時間は別計測で、両者を足して1フレームの費用とはしない。

結果とROM・ラベル・原データは`comparison.json`と`evidence.zip`。
