# 消去範囲の探索とタイル座標変換の比較

60fpsは未達。元の4bpp素材・全縮小寸法・物量・ゲーム時計・通常クロックを維持した実SA-1の統合ROMで比較した。公開ROMは更新しない。

## 試した変更

`--mask-bounds`は物体ごとの左右端更新を取り除き、完成した24帯の32bit転送タイル集合から左右端を一度だけ求める。512Bのbyte探索表を使う。`--mask-bounds-wide-table`は位置ごとの加算も表へ畳み込み、表を2048Bへ拡張する。タイル集合は変えず、空矩形が余分に広げていた消去範囲だけは狭くなる。

元の版には、空帯の0..0と128..0が混在する。また非空帯でも、別の空矩形の影響で左端だけが余分に広がることがある。「元の左右端は常にタイル集合の厳密な外接範囲」という初期の検証仮定はjob122/band19とjob330/band3で棄却された。基準版は集合を包含すること、新方式は厳密一致することを検査し、実バッファの全byte一致で消し残しがないことを確認した。

探索表方式は範囲計算が遅くなり、表示の欠落も減らなかったため不採用。

別の`--dirty-tile-round`は元の範囲計算をそのまま使い、6箇所の`LSR×3 / ASL×2`を`AND #$fff8 / LSR`へ置き換える。16bit Aの全65536値で結果が一致し、最後のC=0、N/Z、V不変も同じ。元の消去範囲・転送集合・画像が完全一致する。こちらは小さな改善候補としてopt-inで残す。

## ボス1900フィールド

基準と近景コピー単独は前の比較の実行結果を再利用し、組み合わせ版を新たに実行した。全方式147画面の独立した画素・VRAM・実PPU照合が合格。全共通packetも一致する。ボスの全世代バッファを基準と直接比較したという意味ではない。

道中job549は範囲3.622155＋消去5.509638＋近景0.301435＋描画12.355945＝21.789173ms。job557の描画は14.694790ms。job429では右端の爆発41（94×74、中心x265）だけで6.206934ms。平均が短くても、これらと出力準備費が残るため60fps達成とは扱わない。

## 次の確認点

過去のCPU dirty版は、すでに次のpacketの範囲計算をSA-1の前frame描画と並行していた。全移管でS-CPUのdirty最大12.26ms＋logic最大10.97msとなり退行済み。同じ移管を新案として繰り返さない。

右端爆発の現行経路は、全native描画の前後で隣接行のはみ出し部分をI-RAMへ退避・復元する。`edge_cpu_game.s`は既にMVNを使い、PPU変換中はDMAとの競合を避けてCPUコピーする。次は退避幅を全shape共通の外接幅から、既存の8行帯のalpha範囲へ絞る費用対効果を調べる。位相・左右反転・奇数nibble・上下端・旧キャッシュ所有権を崩さない設計が必要で、未実装・未測定。過去の逆順kernel・右端prefix・I-RAM窓と混同しない。
