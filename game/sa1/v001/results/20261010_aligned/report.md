# SA-1 描画範囲と転送時間の検証

通常クロック、元の4bpp素材とゲーム処理を維持した実測。60fpsは未達。

ボス試験1200フィールドでは、縦8位相に合わせた不透明範囲の圧縮表で、表示間隔の欠落を30回から13回へ減らした。PPU転送中だけスタック命令による消去へ切り替える試験では1104枚表示、間隔1フィールド1093回、2フィールド7回、3フィールド1回。136画面のフレームバッファ・表示VRAM・背景の画素照合は一致した。SA-1計測は出力記述子の準備前までで、全処理時間とは区別する。

全749寸法×8位相＝5992通りの圧縮表を、最終ROMから読み戻して元画像の縮小結果と照合した。ROM内の近景コード用予約領域を実使用量に合わせ、圧縮表が8MiB以内に収まるようにした。

移動を含む600フィールド試験は510枚表示したが、240枚目のフレームバッファ先頭行に11バイトの不一致がある。これは合格扱いしない。先頭タイル行は画面外でも、バッファ照合の条件は緩めない。

`bossfrontmask`、`bossfrontmask48` は転送量が一回の非表示期間を超えると停止する失敗例。`summary.json` の途中までの表示間隔だけで60fps成功と判定しないよう、末尾の停止時間も判定に追加した。表示面へ途中まで転送することは禁止し、安全な裏面転送への切り替えが必要。

各JSONは試験時の生計測。画素照合の結果・ROMハッシュが付いていないものは検証完了前の記録。`movestress_alignedstackband` は明示的な画素不一致例である。公開ROMは変更していない。次はこの不一致の原因を直し、BW-RAM内の画像保持数を増やして重い描画が連続する区間を検証する。
