# 右端処理の追加比較

大きな爆発などが右端を越えた時の負担を減らす三方式を実測した。全件800field・168画面が実PPU参照で一致し、同一入力のsprite packetも共通世代まで一致した。公開ROMは変更していない。60fpsは未達。

|方式|logic/表示|2field間隔|3field間隔|最大SA-1 ms|
|---|---:|---:|---:|---:|
|比較元の安全BW配置表版|656/645|4|0|22.334215|
|後方走査＋可視prefixをMVNでコピー|645/634|13|1|33.210549|
|IRAM末尾で一行を描いて戻す|649/638|9|1|27.233254|
|端の17byte以上だけIRAM使用＋収まる行は直接描画|656/645|4|0|22.309630|

prefix方式は、最後のSTAから逆向きに調べて可視コード長を求める。従来のhelper全体のIRAMロードを除いたが、行コードのコピー費用が勝つ。56,172kernel・1,092,812境界で、前方走査、後方走査、元の全描画＋クリップの一致を独立に検査した。

IRAM方式は0780..07FFを一行の作業域とし、元のROM行コードをその末尾へ寄せて実行する。越えた部分は0800以降への書込みになり、可視部分だけrawへ戻す。必要なIRAM内容はBW43:2C00..2C7Fに退避して復元する。Mesenの[IRAM実装](https://github.com/SourMesen/Mesen2/blob/master/Core/SNES/Coprocessors/SA1/Sa1IRamHandler.h)は0800..0FFFへの書込みを無視する。初回はこの範囲をmirrorと取り違えて0F80付近を使い、458byteの画素不一致が出たため除外した。実際の0780..07FFを使うv2以降で再検証した。

v3では空の行を飛ばし、行の不透明範囲が画面内なら元のROMコードをrawへ直接実行する。端から17byte未満のはみ出しは従来経路を使う。一部の重い爆発は約6.3msから5.3msへ減ったが、全体の表示待ちは減らない。v2/v3は記録したコマンドで再ビルドし、測定ROMとSHAが一致することも確認した。

`comparison.json` はROM SHAと表示間隔、`commands.json` はビルドコマンド、`evidence.zip` は計測metadata、trace、VRAM、raw、画像。速度の差は単一物体の値と画面全体の値を区別する。
