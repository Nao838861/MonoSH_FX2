# カラー化で変わった輪郭・ポーズの修正

## 結論

カラー化前の絵は実際に変形していた。原因はパレットだけではなく、録画からの切り出しを別のポーズ・縦横比のまま旧寸法へ拡縮したことと、色による背景除去が本体の画素も透明にしたこと。SELECTのモノクロ表示も差し替え後の絵なので、旧版との比較にはならなかった。

今回は、カラー化前から保存してある原画の透明領域と暗部の線を保持し、録画は色の参考として使うように直した。形を差し替えた13素材に加え、白黒のまま残っていた敵弾の第4回転画像を着色。音声コード・音声データ・ゲームロジックは変更していない。

- [実PPU比較1：草木・敵・敵弾](results/visual_fidelity_20261008/ppu_comparison_1.png)
- [実PPU比較2：ボス・自機／自弾・重なり](results/visual_fidelity_20261008/ppu_comparison_2.png)
- [録画のRGB・抽出マスク・元の輪郭・修正版](results/visual_fidelity_20261008/recording_reference_comparison.png)

各PPU画像は、同じ描画リスト・カメラ・位置・大きさ・ポーズをMesenで表示したもの。左がカラー化前の配布ROM、中央が修正前、右が修正後。スクリーンショットをホスト側で描き直したものではない。表示用の拡大だけ最近傍2倍。

## 具体的な破損と対応

- 草01：元の不透明1,610画素のうち1,198画素が欠け、別の場所に136画素が増えていた。明るい葉と暗い内部を背景として除去していた。元の茂みの形と陰影へ戻した。
- 青い敵弾07：元の不透明8,992画素のうち6,260画素が欠けていた。紫の空を判定する条件が青い弾の外周も消し、逆向きの細い芯だけ残っていた。元の回転ポーズと楕円外周を復元した。
- 閉じたEM1の小画像11：開いた羽根の録画を当てていた。元の閉じたポーズを保ち、金属色だけ適用した。12も元の小画像の構造を保持する。
- 木・岩・EM0・ボス胴／顔・ボス弾：輪郭と暗部の細部を保存。録画と位置対応しない弾・小EM1の明暗は転写せず、色相だけ参照した。
- 敵弾37：回転途中の一枚だけ灰色になる指定漏れを修正。録画で確認できる紫系を使う。原作のこの回転位相の色そのものは未確認。
- 炎の共有パレット4：強い黄色の最明部を暖かい白、赤い中間色をオレンジへ変更。ボス弾・爆発・EM0の赤い上部・暖色の敵弾に共通して適用される。

## 原作らしさの評価

保存済みの[原作録画00:58の全画面](results/scenery_fix_20261008/reference_0058.png)も確認した。紫の空、緑の市松床、遠景、赤と青の自機という画面全体の色の方向は維持している。この全画面は今回の固定場面とカメラ・ゲーム時刻が一致する比較ではない。

録画の実RGBを目で比較すると、緑の植物、銀色と赤のEM0、青／紫の敵弾、緑と肌色のボスという色のまとまりは、白黒版より原作に近い。抽出ミスで失われていた量感・閉じた姿・回転方向を戻したことで、修正前より読める絵になった。炎の白い芯も、黄色一色だった時より録画の印象に近い。

ただし、原作画像の完全復元ではない。輪郭の基準はNES版MonoSH由来の既存素材で、録画には別ポーズや重なった別の節が含まれる。元のフル動画はこの検証環境になく、保存済みの切り出しだけを使用した。8×8ごとに透明＋3色、計8組の制約があり、木の葉と幹の境界、ボスの細かな配色、重なった物体の色が同じタイルに混ざる点は残る。色の近さの評価は視覚によるもので、異なるポーズ間のRGB誤差を「原作再現率」とはしていない。

## 検証

- 保存済みカラー25素材、223,169画素で旧原画との透明／不透明マスク差0。暗部の線の変更0。欠損・暗部破壊を故意に入れる負例2件も検出。
- 6組の固定場面について、実エミュレーターのGSU framebufferの輪郭がカラー化前ROMと完全一致。修正前は草木4,619、敵1,964、敵弾4,100、ボス1,757、重なり3,911画素で異なっていた。修正後はいずれも0。
- カラー／SELECTモノクロのframebuffer画素は同一。自機／自弾の固定場面では、最終PPU RGBとOAMも4構成で完全一致。
- 全描画の固定523場面・2,304画像・1,769,472パレットセル、clip・反転・重なり・小幅を含む全FB／OBJ／パレットの照合、通常操作、ポーズ、連射、転倒、ボス撃破から次周、カラー切替を再実行。
- 音源の6種類のSEとポーズ連動を再確認。実機は未検証。処理落ちは今回の反映条件にせず、測定は別途記録する。

通常入力18,000fieldでは17,997回提示、全17,996表示間隔が1field、平均60.0988fps。自然進行中のボス撃破・次周・死亡／復帰も確認した。継続ボス18,000fieldや実機での追加性能試験は今回は行っておらず、常時60Hzを保証する記述にはしない。

最終ROM SHA-256: `84b1372d59d138c6c6d4d9f167d956b077d02598199996086a8a8980c0d76b17`。

結果JSON・ROM hash・実行ログ・全24枚のネイティブPPU画像とVRAM/CGRAM/OAM/FBは [検証フォルダ](results/visual_fidelity_20261008) に保存した。以前の性能・音源一周・DMA限界量の結果は、それぞれの旧ROMに対する履歴。

## 再生成

通常のビルドは保存済み素材を使う。修正アートの再生成は元動画不要。

```sh
python tools/repair_color_silhouettes.py
python tools/verify_color_silhouettes.py
python tools/build_game.py
python tools/benchmark_render.py --name visual --edges --fixtures game/v001/results/boss_scaling_20261008/base_fixtures.json.gz --reuse-build
python tools/verify_render_release.py --name visual --skip-benchmark
python tools/test_game.py --scenario color --frames 360 --timeout 180
python tools/test_audio.py --quick --frames 1400 --timeout 180
```

`capture_visual_fixtures.py` は `--build-dir` で指定したROM・ラベルに同じ6場面を注入し、`--output` へ実PPU画像と状態を保存する。`--mode mono` でSELECT相当のパレットを使用する。旧版はcommit `09d94a43`を再ビルドし、同梱のカラー化前ROMとSHA-256完全一致を確認した。

`bg_color/source.json` と `*_source.png` は従来の録画抽出の出典を保持する。現在の着色規則と変更前後のマスク計測は `bg_color/silhouette_repair.json`、現在の素材比較は `bg_color/comparison.png` にある。元動画からの再取込処理も最後に同じ輪郭保護を適用する。
