# CPUコマンド分類とGSUキャッシュ保持の実装・計測

2026年10月7日。CPUによる完全画面内の指定とGSUの命令キャッシュ保持を実装し、既定構成として採用した。[更新ROM](../../releases/MonoSHFX2_v001.sfc)、[操作](README.md)。表示256×180、内部FB256×192、2bpp、ゲームロジックと描画順を維持する。

**同じボス最重負荷のGSU時間は19.129ms→17.352ms、約9.3%短縮。道中の提示遅延は約0.82%→約0.43%。全場面60fpsには未達。**

## 実装

`packet.s` はソート済み要求の四辺をFB座標で判定する。正の寸法で全体が256×192内なら、転送packet末尾wordに `$8000`（INSIDE）を設定し、それ以外は0を設定する。元のFxDraw、Z/priorityのソートキー、反転・点滅flagsは変更しない。末尾はGSUが使っていなかった領域なので10byte/体を維持する。

`gsu_draw.inc` が制御wordを読み、`gsu_clip.inc` はINSIDEなら座標補正・skip計算を省く。dirty範囲更新、UV設定、描画は共通。クリッピングが必要なら `gsu_clip_edges.inc` で従来の四辺の補正を行い、同じ共通処理へ戻る。完全画面外やzero寸法では画素ループへ入らない。

`gsu.s` は汎用描画ループ・packet展開・dirty範囲更新・UV設定・倍率選択を `$80A0..$8297` の**504byte**へ配置する。512byte以下をアセンブラのassertで保証。座標補正は外へ出し、CACHEを実行せず戻る。汎用経路が続く間、または同じpacked経路が続く間は同じCBRを保持し、描画方式の切替時に再設定する。クリッピング状態の変更だけでは無効化しない。フレーム冒頭のclearと描画の間はキャッシュを切り替える。

## 同じ矩形による4構成比較

自然なプレイから取得した107場面、以前のボス最大負荷、人工64体×2場面、画面端・奇数幅・zero寸法など12場面、計122場面を同じ順で再描画した。各場面を3回連続させ、2/3回目の中央値を比較する。GSU時間には前回範囲のclear、packet展開、clip/UV、描画、flush、DMA区間作成を含む。CPUコマンド生成時間は別に計測し、GSU時間へ加算しない。

|場面|変更前|CPU分類のみ|cache変更のみ|両方|GSU時間短縮|
|---|---:|---:|---:|---:|---:|
|以前のボス最大負荷・14コマンド|19.129ms|19.061ms|17.558ms|17.352ms|9.29%|
|完全画面内64体・人工負荷|19.426ms|19.072ms|12.750ms|11.767ms|39.43%|
|左端でclipされる64体・人工負荷|14.422ms|15.043ms|8.540ms|8.570ms|40.58%|

107実ゲーム標本のGSU時間合計は約13.63%減少。これは標本を等回数再描画した集計であり、実プレイの時間加重平均ではない。描画がほとんどない撃破後の3標本は約0.851ms→0.957msで悪化し、それ以外の104標本は改善した。

CPU packet生成は107標本平均で約0.513ms増加。上記のボス場面では約2.311ms→3.011ms。分類だけを追加すると一部場面で悪化するため、cache保持と合わせて採用する。人工64体はソート自体も重い試験で、通常ゲームのfpsとして扱わない。

GSUのCACHE実行直前にCBRを読み、変更による無効化を計数した。ボス標本では30回→4回、人工64体では129回→2回。これはCBR変更の回数であり、命令キャッシュの全ヒット率やROM読出しbyte数ではない。

4構成の完成画像は合計2,890枚。コマンドと全49,152画素を独立したPythonのclip・反転・UV・透明合成と照合し、同じ標本のFB hashも4構成で一致した。測定終了時にGSUだけ完了しDMA未完了だった画像は比較から除外した。

Mesenは `D:\HomeBrew\Mesen\Mesen.exe` と同じバイナリの専用コピー。NTSC・GSU速度100%、追加scanline=0。変更前は前回保存した18,000field、変更後も18,000fieldを観測。射撃を保ち、ボス中は自機が顔を追う同じ入力アルゴリズム。ゲーム状態の強制変更はしていない。速度により進行量が変わるため、同じ物理fieldの画像同士の比較ではなく、区分ごとの提示頻度を比較する。

今回の道中・ボス戦では3field以上の提示間隔はない。NTSCの1fieldは約16.639ms・60.099Hz、60field窓は約0.998秒。道中の平均は実際に観測した約248秒／約253秒の提示間隔から算出した。

**道中でも生存中に処理落ちは残る。** 生存中だけでは54/11,136回（0.485%）→65/11,407回（0.570%）で、改善していない。変更後の道中遅延65回中、CPU終了がGSU終了より遅かったものが49回、GSUが遅かったものが16回。CPU分類の費用でCPU側の余裕が減る点は次の課題。道中全体の改善だけで通常操作中も改善したと結論しない。

変更後の道中最大GSU時間は16.948ms（論理更新4879、地形5・敵3・GSUコマンド9）、CPU最大は15.613ms。新たな通常プレイで観測したボス最大GSUは17.452msで、上記の固定標本とは少し異なる場面。直前DMA・開始準備・合流後処理・固定設定＋OAMを含めた連続60HzのGSU枠はこの場面で約13.789msなので、**さらに約21%のGSU時間短縮が必要**。全入力や実機の最大負荷を保証する値ではない。
