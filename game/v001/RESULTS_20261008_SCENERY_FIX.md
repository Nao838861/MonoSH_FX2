# 遠景の地平線・透過・空の修正

録画00:58と修正前後の実PPU画像を比較して修正した。[比較画像](results/scenery_fix_20261008/comparison.png)、[二重スクロールGIF](results/scenery_fix_20261008/parallax.gif)、[カメラ3段階](results/scenery_fix_20261008/camera_heights.png)を保存する。比較は地面の開始行を揃えた同じ倍率の切り出し。録画とSNESではカメラの横位置が異なる。

## 原因と修正

- **地平線**：地面HDMAの内部値111に対し、実際に地面が始まるのは104＋カメラoffsetだった。森は112行まで重なっていたため、山と森を9ドット上げ、103行で終える。市松地面が104行から地平線へ連続する。
- **森の透過**：緑の色判定に空の緑まで混じり、山の画像にも森を除去した穴が残っていた。空だけの列から行ごとの背景色を測り、森の輪郭を取り直した。山は稜線から裾まで不透明にし、森で隠れていた部分を録画内の最寄りの紫・白・青の画素で補完した。
- **グラデーション**：従来は録画124..144行から取り、紫の一定色を7行含んだまま緑の終端を切り落としていた。130行の基色と131..150行の変化を取り、実画面75..95行へ配置した。
- **山頂の白**：2bpp用の量子化で小さい白が薄紫へ吸収されていた。録画の白い稜線の代表色を候補へ残し、白を保つ。

上下移動には山・森・グラデーションが一緒に追従する。横移動は森BG1が山BG4の2倍。Mode0・共有8KiBのCHR・間接HDMA表10bytes×3・空の色列84bytesを維持した。遠景は共有203/512tile。既存のボス縮小画像・大きい自弾・CPU/GSU最適化を保つ。

## 検証

`tools/test_game.py --scenario scenery --frames 720`を追加し、キャラを消した実PPU画像と二重スクロールGIFを取得する。従来の`display`では地上物と自機を重ねて検査する。

両シナリオのカメラoffset 0・32・64で最終RGB全画素を照合し、さらに次を独立に検査する。

- 森の全512列が地面の開始位置より下へ出ない。
- 山の下7行は全512列で不透明で、別速度の森が抜けても山裾がある。
- HDMAの開始位置・全21色が録画の空の色列と一致する。
- 山のパレットに白い稜線の色が残る。
- 山と森の横スクロール比が1対2。

自機・弾の17pose・4反転・16サイズ、最悪18 OBJを含む85標本と最終PPU66画面68,057画素、静止射撃1,800field、ボス撃破・次周2,600fieldを確認した。通常入力6,000fieldは5,978画像、道中・ボス・撃破後とも提示遅延0回、60.099fps。[集計](results/scenery_fix_20261008/performance.json)と圧縮timingsを保存した。以前の18,000field×2の検証は以前のROMに対する履歴として扱う。

更新ROMのSHA-256は`12e300196644619e5b0710859c71fd70d8d3294d2cf9c7cc54c4245523798978`。公開用の別チェックアウトから生成したROMとも全byteが一致した。

自己評価：前回の全画素照合は間違った位置・透過マスクをそのまま参照していたため、原作との差を検出できなかった。今回は録画・修正前ROM・修正後ROMを実画像で比較し、地平線、山裾の不透明、空の長さを別条件として追加した。録画で隠れた山の画素は補完であり、原画そのものの復元ではない。実機は未確認。

再実行：`python -X utf8 tools/build_game.py`、`python -X utf8 tools/test_game.py --scenario scenery --frames 720 --timeout 90`、`python -X utf8 tools/test_game.py --scenario display --frames 720 --timeout 90`。保存済みの三カメラの照合は`tools/verify_game_display.py`の`verify()`へ結果の`display`または`scenery`フォルダを渡して実行できる。
