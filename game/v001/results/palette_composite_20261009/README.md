# 原作画像を合成して共通16色へ減色する比較

2026年10月9日。ユーザーの依頼：

> 16色使ってこのクオリティ？原作の画像で、ボス戦のボスと弾がある絵にザコと木、爆発を合成したものを16色に減色したらどうなる？やってみて。

土台は録画86.5秒のボス・光弾・自機・背景。38秒のザコ、32.133333秒の紫弾と赤青の二発、50秒の木、77秒の爆発を追加した。各切り抜きの元矩形と透過画像も同じフォルダーへ保存した。爆発では白・灰・黒の内部を残すため、赤い部分だけの抽出ではなく、外の紫空と背後の緑を除いている。切り抜きの不透明画素のRGBが録画の元矩形と一致することをassertした。

合成原画像は19,316色。画像全体からMedian Cut（Pillowの`kmeans=20`指定）で共通パレットを作り、各色をSNESのRGB5へ丸めた。色数はディザなし・ありとも**実使用16色**であり、物体別のパレット、現行ROMの手選びパレットは使っていない。空・地面・自機もこの共通16色に含む。透明色は予約しない静止画の比較であり、ゲームの合成バッファの透明＋15色とは区別する。

## 結果から分かること

16色でも、原画像にあるボスの鱗・腹の段階的な陰影・爆発の内部模様が相当残る。色数だけで前版の二段階の塗りを説明することはできない。前版は元の白黒原画を明暗二段階の同系色へ着色しており、元のカラー画像に存在する階調自体を入力から失っていた。

一方、この単一画像から作った16色では、木の明るい緑の陰影、紫弾、青弾、自機の青などが損なわれる。Floyd–Steinbergは色の中間を補うが、広い空と地面に粒が出る。この比較ではディザなしの方が輪郭と背景を読み取りやすい。今後の素材改善は、原作のカラー画素と陰影を保持した入力から共通パレットを決め、その結果を見て調整すべきであり、「白黒の二値化が一致する」ことだけを色の品質の根拠にしない。

これは指定された静止画の減色実験。ROM・素材生成経路・既存パレットは変更していない。パレットはこの合成画像へ最適化しており、全ステージ・全色アニメでの品質を確認したものではない。

```powershell
python -X utf8 tools/probe_16color_composite.py
```

元動画は既存の `D:\HomeBrew\MonoSH\tmp\スペースハリアー録画１.mp4`。別の保存場所は `--video <パス>` で指定できる。ffmpeg、Pillow、NumPyを使う。生成時に画素の保存、実使用色数、4bitインデックスの範囲、RGB5で表現可能な色だけであることを検査する。
